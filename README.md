# Infosys Limited — Equity Research & Valuation

A source-traceable equity research and valuation portfolio project using six years of consolidated Ind AS financial statements (FY2021–FY2026), a five-year forecast (FY2027–FY2031), an FCFF discounted cash flow model, trading comparables, and reproducible Python/SQL analysis.

> **Scope:** Educational portfolio analysis only. This is not investment advice, an independent audit, a compliance opinion, or a guarantee of valuation accuracy.

## Project highlights

- Consolidated Ind AS historical financial analysis for FY2021–FY2026.
- Source register, source-line traceability, reconciliation logs, and selected arithmetic/consistency checks.
- Analyst normalization and forecast assumptions, with bear/base/bull scenarios.
- FCFF DCF valuation using CAPM/WACC, terminal value, and sensitivity analysis.
- Trading-comparables cross-check against TCS, HCLTech, and Wipro.
- Python/Jupyter workflow for data reshaping, validation, trend analysis, visualization, and SQLite database generation.
- SQL analysis in SQLite and a separately migrated MySQL 8.0 analytical copy.

## Quick start

### 1. Review the model

Open `workbook/Infosys_Final.xlsx`. Start with the **Investment Summary** and **Start Here** sheets, then review the DCF, Trading Comparables, forecast, source register, source trace, audit sheets, and reconciliation log.

### 2. Set up Python

Use Python 3.10+ and install the listed dependencies:

```bash
python -m pip install -r requirements.txt
```

### 3. Run the notebook

Open Jupyter Notebook or JupyterLab with the repository root as the working directory, then open `notebooks/Infosys_Python_SQL_Analysis.ipynb`.

The notebook is configured to read `workbook/Infosys_Final.xlsx` and write the rebuilt database to `database/Infosys_Analysis.db`. Run the cells from top to bottom. The workflow reshapes historical data, runs selected checks, calculates trend indicators, creates charts, and rebuilds the SQLite database.

The committed `database/Infosys_Analysis.db` is a ready-to-query snapshot. The notebook-generated SQLite database is the canonical analytical database; MySQL is an additional migrated copy.

### 4. Run the SQLite queries

Open `database/Infosys_Analysis.db` with a SQLite client and run the statements in `sql/Infosys_SQL_Analysis.sql`.

### 5. Optional: use MySQL Workbench

The MySQL workflow was completed using MySQL Server 8.0.46 and a separate schema named `infosys_valuation`.

- Do not modify unrelated schemas (for example, `upi_analytics`).
- Install the connector if needed: `python -m pip install mysql-connector-python`.
- Create/select an empty `infosys_valuation` schema.
- Run `python scripts/Infosys_SQLite_to_MySQL_Migration.py` from the repository root. The script locates `database/Infosys_Analysis.db` automatically.
- The migration script requests the password at runtime; never place credentials in code or commit them.
- Open `sql/Infosys_MySQL_Analysis.sql` in MySQL Workbench and execute one highlighted query at a time.

**Previously validated MySQL copy:** five tables, 343 rows total:
- `annual_financials`: 198
- `annual_ratios`: 84
- `annual_trend`: 6
- `quality_checks`: 31
- `source_register`: 24

The SQLite-to-MySQL migration was checked row-by-row and value-by-value and returned **ALL PASS** in the working environment. Re-run the validation after any future migration or data refresh.

## Important analytical definitions and limitations

- Historical primary basis: consolidated Ind AS FY2021–FY2026. IFRS figures are separate cross-checks and are not mixed into the primary historical series.
- **CFO less capex** is an analyst-calculated proxy, not company-reported free cash flow or FCFF.
- Missing historical values remain blank/NULL; they are not treated as zero.
- DCF working capital is a narrow trade-receivables-less-trade-payables proxy. Contract assets/liabilities and other operating balances are not fully mapped across all six years; this is a material FCFF limitation.
- Historical tax expense divided by PBT is only a proxy for operating tax. Forecast tax is an analyst assumption.
- Beta, cost of debt, terminal growth, forecast assumptions, and some market inputs are estimates or third-party snapshots. Refresh and verify them before external publication.
- The share count is an approximate market-data estimate and should be verified against the latest primary filing before external publication.
- Passing arithmetic checks demonstrates selected internal consistency; it does not prove source transcription accuracy or replace a source audit.

## Data and reproducibility notes

- The workbook is the central model and source-evidence workspace.
- The notebook rebuilds the SQLite database from the workbook.
- MySQL is a validated analytical copy, not the source of truth. It does not update automatically when the workbook or SQLite database changes.
- To refresh the project, update actuals from official consolidated statements, preserve accounting-basis separation, update source/reconciliation records, recalculate the workbook, rerun the notebook, and separately refresh the MySQL copy.
